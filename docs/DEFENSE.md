# Разбор проекта для защиты

## Краткое представление

«Я разработал TaskFlow — небольшое Flask-приложение для управления задачами. Оно позволяет добавлять, изменять, завершать, фильтровать и удалять задачи. Данные сохраняются в SQLite. Для проверки использованы модульные, интеграционные и системные тесты. GitHub Actions запускает проверки, а после успешного push в main публикует Docker-образ».

Перед защитой самостоятельно пройдите основной сценарий и прочитайте четыре Python-файла в `app/`, чтобы уверенно объяснять реализацию.

## Сценарий демонстрации (5–7 минут)

1. Откройте приложение. Добавьте «Подготовить отчёт» и «Защитить проект».
2. Измените название первой задачи, завершите вторую и покажите фильтр «Выполнено».
3. Перезагрузите страницу: данные остаются. Удалите одну задачу.
4. Покажите `validation.py`: `strip()`, проверка пустой строки, ограничение длины.
5. Покажите `routes.py`: POST-запрос, SQL с параметрами, `commit()`, перенаправление.
6. Запустите `pytest --cov=app`. Покажите по одному тесту каждого уровня.
7. На GitHub покажите workflow, его реальный результат и опубликованный пакет, если публикация выполнена.

## Путь запроса

Браузер → Flask-маршрут → валидация → SQLite → HTML-шаблон → браузер.

Пример добавления: форма отправляет POST `/tasks`. Flask-WTF проверяет CSRF-токен. `validate_title()` проверяет и очищает текст. SQL вставляет строку, `commit()` сохраняет изменение. Ответ перенаправляет на главную страницу. Такой подход называется POST/Redirect/GET и предотвращает повторную отправку формы при обновлении страницы.

## Вопросы и ответы

**Почему Flask?** У него небольшой набор основных понятий: маршруты, запросы, шаблоны, конфигурация. Этого достаточно для небольшой задачи.

**Почему SQLite?** База находится в одном файле и не требует отдельного сервера. Для учебного однопользовательского приложения это упрощает запуск.

**Что такое фабрика приложения?** `create_app()` создаёт новый Flask-объект. В тестах можно передать путь к временной базе и тестовый ключ, не меняя рабочую конфигурацию.

**Почему не ORM?** В проекте одна маленькая таблица. Обычный SQL позволяет явно увидеть, как сохраняются и читаются данные.

**Чем отличаются уровни тестов?** Модульные — отдельная функция; интеграционные — Flask и база вместе; системные — весь сценарий в реальном браузере и через HTTP.

**Что даёт CI?** Каждое изменение проверяется автоматически в одинаковой среде, включая разные версии Python. Можно увидеть ошибку до принятия изменения.

**Что даёт CD?** После успешных тестов автоматически создаётся и публикуется готовый контейнер. Это continuous delivery. Установка этого контейнера на внешний сервер — отдельный этап развёртывания.

**Как защищены запросы?** SQL использует параметры; шаблоны экранируют пользовательский HTML; изменения требуют POST и CSRF-токен. Права пользователей не реализованы, поскольку приложение однопользовательское.

**Что означает покрытие?** Какие строки и ветвления Python выполнялись в тестах. Высокое покрытие полезно, но само по себе не доказывает отсутствие ошибок.

**Что можно улучшить?** Добавить авторизацию и владельца задачи, сроки и приоритеты, затем подключить PostgreSQL и развёртывание на выбранный сервер. Эти функции специально исключены, чтобы проект оставался понятным.
