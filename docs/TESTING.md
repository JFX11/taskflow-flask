# Требования и план тестирования

## Область проекта

Однопользовательское веб-приложение управления задачами. Одна сущность `tasks`: `id`, `title`, `done`. Данные хранятся в SQLite. Интерфейс на русском.

## Проверяемые требования

| Требование | Уровни проверки | Основные случаи |
| --- | --- | --- |
| Создание задачи | unit, integration, system | Кириллица, emoji, обрезка пробелов, сохранение |
| Валидация | unit, integration, system | Пустая строка, пробелы, длины 120 и 121, отсутствующее поле |
| Редактирование | integration, system | Открытие формы, сохранение, отмена, ошибка без изменения БД |
| Завершение и возврат | integration, system | Два последовательных переключения |
| Фильтрация | unit, integration, system | Все статусы, неизвестный фильтр, пустая категория |
| Статистика и сортировка | integration | Общий счётчик, выполненные/активные, новые задачи сверху |
| Удаление | integration, system | Удаляется выбранная задача, результат сохраняется |
| Сохранение | integration, system | Новое приложение с той же БД, перезагрузка страницы |
| Ошибки HTTP | integration, system | 404 для отсутствующей задачи, 405 для GET-изменения, 413 |
| Защита данных | integration, system | Экранирование HTML, SQL как текст, отсутствующий/неверный/правильный CSRF |
| SQLite | integration | Повторная инициализация, закрытие соединения, отсутствие чужих данных |
| Адаптивность | system | Добавление и удаление при ширине 390 px, отсутствие горизонтального скролла |
| Работоспособность | integration | `/health` возвращает 200 и проверяет соединение с БД |

## Почему три уровня различаются

Модульный тест вызывает чистую функцию напрямую. Он локализует ошибки правил валидации.

Интеграционный тест отправляет запрос через Flask test client, выполняет реальный SQL и проверяет результат. Он проверяет взаимодействие маршрутов, базы и шаблонов, но не запускает сетевой сервер или браузер. В большинстве этих тестов CSRF отключён для удобства подготовки данных; отдельная проверка включает его обратно.

Системный тест запускает приложение целиком и управляет Chromium через Playwright. Он взаимодействует с видимыми полями, ссылками и кнопками; настоящая CSRF-защита включена. Основной сценарий: добавить → перезагрузить → изменить → завершить → проверить фильтры → вернуть в работу → удалить → перезагрузить.

## Критерии приёмки

- Все тесты проходят, Ruff не находит ошибок.
- Покрытие Python-кода с ветвлениями не ниже 90%.
- Пользователь выполняет основной сценарий на десктопе и узком экране.
- CI запускается в GitHub Actions; при падении тестов публикация не начинается.
- После успешного push в `main` появляется Docker-пакет с тегом коммита.

Покрытие оценивает исполненные строки и ветки Python, а не полноту всех возможных пользовательских случаев. Нагрузочные тесты, авторизация, несколько одновременных пользователей и тестирование Safari/Firefox выходят за объём проекта. Docker и GitHub Actions требуют отдельной проверки в соответствующей среде; результат локального pytest не подтверждает их запуск.
