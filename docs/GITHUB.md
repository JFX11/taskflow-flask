# Публикация на GitHub

## Загрузка репозитория

Создайте публичный репозиторий `taskflow-flask` в своём аккаунте. При публикации через Git не добавляйте на GitHub первоначальный README или `.gitignore`: они уже включены в проект.

Из папки проекта выполните, подставив свой логин:

```bash
git init -b main
git add .
git commit -m "Build TaskFlow Flask app with tests and CI/CD"
git remote add origin https://github.com/YOUR_USERNAME/taskflow-flask.git
git push -u origin main
```

Если репозиторий уже инициализирован и коммит создан, начните с `git remote add`. Для HTTPS GitHub использует авторизацию через менеджер учётных данных / GitHub CLI или токен, а не обычный пароль. Не помещайте токены в код, URL remote или переписку.

Вариант при установленном и авторизованном GitHub CLI:

```bash
gh repo create taskflow-flask --public --source=. --remote=origin --push
```

`.gitignore` исключает окружение, SQLite, `.env` и локальные отчёты. Workflow находится в скрытой папке `.github` — при ручной загрузке нельзя её пропустить.

## Проверка CI/CD

1. Откройте вкладку **Actions** и workflow **Tests and delivery**.
2. Дождитесь результатов трёх заданий `tests` и задания `delivery`.
3. Откройте артефакты отчётов, затем раздел **Packages** аккаунта или репозитория.
4. Найдите контейнер `taskflow-flask` с тегами `latest` и SHA коммита.

Для демонстрации блокировки создайте отдельную ветку, намеренно измените ожидаемое значение в тесте и откройте PR: CI станет красным, публикация для PR не запускается вообще. Верните тест, чтобы показать успешную проверку. Защита ветки от merge при красном CI включается отдельно в настройках GitHub — workflow сам её не настраивает.

Первичная видимость контейнерного пакета может быть приватной, даже если репозиторий публичный. При необходимости сделайте пакет публичным в его настройках либо авторизуйтесь в GHCR. Настройки организаций могут ограничивать запись пакетов или использование Actions.

## Использование опубликованного образа

```bash
docker pull ghcr.io/YOUR_USERNAME/taskflow-flask:latest
docker run -d --name taskflow -p 127.0.0.1:8000:8000 \
  -e SECRET_KEY="YOUR_LONG_RANDOM_SECRET" \
  -v taskflow-data:/data \
  ghcr.io/YOUR_USERNAME/taskflow-flask:latest
```

Логин в адресе GHCR должен быть в нижнем регистре. В PowerShell используйте одну строку вместо переносов `\`.

Проверка: откройте `http://127.0.0.1:8000/health` и главную страницу. Чтобы обновить приложение, загрузите новый образ и пересоздайте контейнер с тем же volume. Не удаляйте volume, если нужны сохранённые задачи.
